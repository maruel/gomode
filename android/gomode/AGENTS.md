# Go Mode Android App

Go Mode is a Kotlin/Compose Android app with package `com.fghbuild.gomode`.
It is a thin native shell around backend-hosted mobile web frontends.

Read `../AGENTS.md` first for shared Android rules. Use
`../../docs/ANDROID_SHELL.md` as the canonical architecture plan.

## Product Boundary

Go Mode is the Android app for backend-hosted mobile frontends.

Go Mode owns native platform capabilities:
- Bootstrap settings before a WebView can load.
- WebView hosting and host-mode compatibility negotiation.
- Android notification permission and hosted-service notifications.
- Microphone/audio routing and foreground voice services.
- Screenshot capture when native MediaProjection is required.
- Halo/BLE integration when the shell owns the native capability.

The backend-hosted web frontend owns screen-mode product UI. Do not copy caic
task list, task detail, diff, process, widget, or screen-mode Compose UI into
Go Mode.

Go Mode must not depend on caic domain APIs or SDK types. In Go Mode app code
and tests, do not import `com.caic.sdk.v1`, create/list/input caic tasks, or
assert caic-specific routes such as `/task/...`. Treat caic as one possible
hosted web app, opaque behind the WebView.

## Architecture

```text
MainActivity
  -> GoModeApp
      -> native settings fallback
      -> active service instance
      -> WebShellScreen
          -> WebView loading backend-hosted frontend
```

The target architecture also includes app-scoped monitoring, notifications,
voice endpoint behavior, screenshot capture, and Halo/BLE. Add these as native
capabilities only when the WebView shell needs them.

## Current Shape

- `MainActivity.kt`: single-activity host.
- `data/SettingsRepository.kt`: persisted service-instance settings.
- `ui/GoModeApp.kt`: root Compose surface.
- `ui/settings/SettingsScreen.kt`: native settings fallback.
- `ui/web/WebShellScreen.kt`: WebView shell.

## Rules

- Package/application ID is `com.fghbuild.gomode`; do not reuse caic package
  names, DataStore names, notification channels, deep-link schemes, or test
  package names.
- Keep service identity explicit. Settings should be keyed by service type and
  service instance, not only by URL.
- Load backend-hosted web frontends; do not bundle frontend assets into the APK.
- Do not link Go Mode against caic API clients, generated SDKs, task DTOs, task
  routes, or other caic product concepts.
- Do not proxy normal caic API calls through a JavaScript bridge.
- Keep the JavaScript bridge narrow, versioned, and capability-oriented.
- Android back handling must account for SPA route ownership, not only
  `WebView.canGoBack()`.
- Platform WebViews need real Android resource IDs for instrumented tests.

## Instrumented Testing

`make android-check` compiles the app and instrumented tests; compilation does not
replace running them. Run the applicable instrumented tests on an emulator after
Android changes. If none is installed or running, use `make android-start-emulator`
to provision and start the stock AVD. Lack of an emulator is not a reason to skip
these tests. Run focused native classes through `connectedDebugAndroidTest`, and
`make android-voice-e2e` when voice transport changes. `make android-e2e`
starts or reuses an emulator, serves a generic hosted frontend fixture, and
runs shell-owned instrumented behavior. New instrumented coverage should
validate shell-owned behavior through a generic hosted frontend. Mark tests
that use the standalone fixture with `@StandaloneHostedFixture`; the E2E runner
selects that annotation and excludes host-specific cases.

## Checks

| Change | Required validation |
| --- | --- |
| Any Go Mode Android change | `make android-check` and applicable emulator instrumented tests |
| Networking, SSE, service monitoring, WebView loading, settings, host-mode behavior, or native shell routing | Focused Robolectric tests, `make android-check`, and emulator instrumented coverage |
