# Go Mode Android App

Go Mode is a Kotlin/Compose Android app with package `com.fghbuild.gomode`.
It is a thin native shell around backend-hosted mobile web frontends.

Read `../AGENTS.md` first for shared Android rules. Shell contracts live in the
header comments of their owning source files; the File Index below locates them.

## Product Boundary

Native code owns service bootstrap, WebView hosting, bridge compatibility,
permissions, notifications, voice, Telecom calls, settings, and Halo. The
backend-hosted web frontend owns product UI: keep product lists, detail views,
diffs, processes, and widgets there. Add a native capability only when the
WebView shell needs it.

Go Mode app code and tests must not depend on a host's domain APIs or SDK
types, perform product operations, or assert host-specific routes. Treat
each hosted web app as opaque behind the WebView.

## Rules

- Package/application ID is `com.fghbuild.gomode`; do not reuse host package
  names, DataStore names, notification channels, deep-link schemes, or test
  package names.
- Keep service identity explicit. Settings should be keyed by service type and
  service instance, not only by URL.
- Load backend-hosted web frontends; do not bundle frontend assets into the APK.
- Do not link Go Mode against host API clients, host SDKs, domain DTOs,
  routes, or other product concepts.
- Do not proxy host product API calls through a JavaScript bridge.
- Keep the JavaScript bridge narrow, versioned, and capability-oriented.
- Android back handling must account for SPA route ownership, not only
  `WebView.canGoBack()`.
- Platform WebViews need real Android resource IDs for instrumented tests.

## Instrumented Testing

`make android-test` compiles the app and instrumented tests; compilation does not
replace running them. Run the applicable instrumented tests on an emulator after
Android changes. If none is installed or running, use `make android-start-emulator`
to provision and start the stock AVD. Lack of an emulator is not a reason to skip
these tests. `make android-e2e` runs every model-free app test and the independent
Telecom fixture APK, supplying both generic hosted and controlled gateway fixtures.
Focus a class or method with
`uv run --locked python scripts/android_e2e.py --class <Class[#method]>`; add
`--module telecom` for the independent Telecom APK, or use `--module app` to run
only app instrumentation. The default runner requires an emulator without an
existing secure credential and refuses unsupported devices before mutation.

Ordinary tests need no inclusion annotation. Mark real inference or large model
transfers with `@ModelAcceptance` and documentation captures with
`@DocumentationCapture`; these are excluded even from focused model-free runs.
Run expensive acceptance explicitly through `connectedDebugAndroidTest` with its
class and opt-in arguments. Tests of controlled inference, model controls, and
bounded storage remain ordinary. Mark microphone-prompt cases with
`@DeniedMicrophonePermission`; the runner resets prompt state outside the app
process, executes them separately, and restores the prior microphone grant.
Use `@ModelFreeSpeech` with `ModelFreeSpeechRule` when a case needs the controlled
platform recognizer. No downloaded speech or language models are required.

CI runs `make android-e2e-ci`, which skips `@LocalEmulatorOnly` cases; each
instrumentation APK declares its own copy. CI keeps one emulator case per
mechanism. Mark a new case `@LocalEmulatorOnly` when it repeats a covered
mechanism in another state, waits on a real production deadline, or measures
device performance. `make android-e2e` still runs every model-free case.
Put Compose tests that need no real WebView, audio, Telecom, or system UI under
`src/test` with Robolectric; use `@GraphicsMode(NATIVE)` when they measure text.

## Checks

| Change | Required validation |
| --- | --- |
| Any Go Mode Android change | `make android-lint android-test` and applicable emulator instrumented tests |
| Networking, SSE, service monitoring, WebView loading, settings, host-mode behavior, or native shell routing | Focused Robolectric tests, `make android-lint android-test`, and emulator instrumented coverage |
